# Unique Combinations Using Backtracking

## Problem Statement

Aryan is helping his friend plan gift packages with a total budget of `N` rupees. He wants to find all unique ways to spend the entire budget using different combinations of gift prices, making sure no combination is counted twice by rearranging the prices.

## Note

Two combinations are considered the same if one is a permutation of the other. For example, `[1,2,1]` and `[1,1,2]` are not unique.

All combinations must be printed in non-decreasing order. For example, `[1,2,1]` will be printed as `[1,1,2]`.

The order of printing all combinations must be in lexicographical order.

Use backtracking to solve the problem.

## Input Format

The input consists of a single integer `n`, which represents the number to be broken down.

## Output Format

The output prints a single line containing all combinations in the format of a list of lists:

```text
[[a, b, ...], [c, d, ...], ...]
```

where each inner list represents one combination printed in non-decreasing order, and all combinations are printed in lexicographical order.

Refer to the sample output for the exact formatting specifications.

## Constraints

* `1 ≤ N ≤ 25`

```

**Output**

```

### Case 3

**Input**

```text

```

**Output**

```text
[[1, 1, 1], [1, 2], [3]]
```

## Approach

1. Use backtracking to generate all possible combinations whose sum is exactly `N`.
2. Maintain the smallest value that can be selected at each step using a variable called `start`.
3. This ensures that every combination is generated in non-decreasing order.
4. Try every number from `start` up to the remaining value.
5. Add the selected number to the current combination and recursively generate the remaining values.
6. When the remaining value becomes `0`, a valid combination has been found.
7. Store the combination in the result.
8. Remove the last selected number and try the next possible value.
9. Since smaller values are explored first, the generated combinations are automatically in lexicographical order.

## Java Solution

```java
import java.util.*;

class Solution {

    static int n;
    static ArrayList<ArrayList<Integer>> result = new ArrayList<>();
    static ArrayList<Integer> current = new ArrayList<>();

    static void findCombinations(int remaining, int start) {

        // A valid combination is found
        if (remaining == 0) {
            result.add(new ArrayList<>(current));
            return;
        }

        // Try all possible values
        for (int value = start; value <= remaining; value++) {

            current.add(value);

            // Use the same value again if required
            findCombinations(remaining - value, value);

            // Backtrack
            current.remove(current.size() - 1);
        }
    }

    static void printResult() {
        System.out.print("[");

        for (int i = 0; i < result.size(); i++) {
            System.out.print("[");

            ArrayList<Integer> combination = result.get(i);

            for (int j = 0; j < combination.size(); j++) {
                System.out.print(combination.get(j));

                if (j < combination.size() - 1) {
                    System.out.print(", ");
                }
            }

            System.out.print("]");

            if (i < result.size() - 1) {
                System.out.print(", ");
            }
        }

        System.out.println("]");
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        n = sc.nextInt();

        findCombinations(n, 1);
        printResult();
    }
}
```

## Complexity Analysis

* **Time Complexity:** `O(2^N)` in the worst case, as backtracking explores possible partitions of `N`.
* **Space Complexity:** `O(N)` for the current combination and recursion stack, excluding the space used to store the result.
